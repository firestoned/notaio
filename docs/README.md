# notaio documentation

The documentation site is built with [MkDocs Material](https://squidfunk.github.io/mkdocs-material/)
and published to <https://firestoned.github.io/notaio/> on every merge to `main`.

```sh
make docs         # build into docs/site/ (strict: a broken link or missing include fails)
make docs-serve   # live reload at http://127.0.0.1:8000
make docs-clean   # remove docs/site/ and docs/.venv/
```

Needs Python 3.10+ and [Poetry](https://python-poetry.org/).

## Layout

The canonical documents stay where the rest of the repository refers to them, and the site pulls
them in with `pymdownx.snippets`, so there is exactly one copy of each:

| Canonical file | Site page |
| --- | --- |
| `docs/architecture.md` | `src/architecture.md` |
| `docs/threat-model-mapping.md` | `src/security/threat-model-mapping.md` |
| `docs/framework-mapping.md` (generated by `make air`) | `src/security/framework-mapping.md` |
| `docs/adr/NNNN-*.md` | `src/adr/NNNN-*.md` |
| `ROADMAP.md` | `src/roadmap.md` |
| `deploy/profiles/builtin.yaml` (generated by `make manifests`) | `src/reference/profiles.md` |

Edit the canonical file, never the include stub. Pages that exist only on the site (home, security
overview, developer guide) live under `src/` directly.

A new ADR needs a stub in `src/adr/` and a `nav` entry in `mkdocs.yml`.
